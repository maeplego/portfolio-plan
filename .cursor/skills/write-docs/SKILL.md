# Write portfolio docs

1. Read `portfolio-plan/02-documentation.md` (required set).
2. Use `calendar/docs/` as the layout example when starting a new `docs/` tree.
3. Do **not** create empty `docs/` for untouched Pxx.
4. Short implementation design stays in `portfolio-plan/<project>/DESIGN.md`.
5. Precedence when conflicting: **tests/code → DESIGN.md → docs/** (update docs to match).
6. Never claim unimplemented behavior as acceptance criteria (“できる”).
7. Hiring-facing tone OK; do not label docs as「面接用」.
