## 結論（判断）

| 問い | 判断 |
| --- | --- |
| 新規 Pxx を作るか | **作った（P16 / `pf-payroll`）**。空の `docs/` は規制名乗り前に無理に増やさない |

| P14 personal-finance に載せるか | **載せない**。個人家計であり法人給与・税務ではない |

理由（overview の統合基準に照らす）:

1. **アクターが違う** — 従業員打刻（P09）≠ 給与計算担当／税理士フロー（P16）≠ 個人家計（P14）
2. **一貫性境界が違う** — 分単位の勤怠イベント vs 円・控除・法定帳票 vs 家計カテゴリ
3. **物語** — 「勤怠の延長で給与」は責任範囲が爆発し、既存の「名乗らない」契約を壊す
4. **元アイデア 01–30 に給与税務は無い** — 商用ロードマップ由来の **第 16 製品** として明示するのが正しい

#### P16-規制名乗り で「どうすればよいか」（実務）

今すぐ法令準拠を名乗らない。**P16-デモ のまま販売・提案し、規制名乗りは専門家レビュー後の別ゲート**にする。

| ステップ | やること | やらないこと |
| --- | --- | --- |
| 1. 現状維持 | カタログは「対象外／デモ」。disclaimer・`legalEffect: false` を壊さない | 提案書に「源泉・年末調整できます」と書く |
| 2. レビュー準備 | 対象法令・帳票一覧、計算根拠の版管理案、データ保持、テナント境界を 1 枚にまとめる | レビュー前に本番向け税率表をハードコードして「準拠」とする |
| 3. 専門家 | 税理士／社労士（必要なら弁護士）に **有償レビュー**。記録を `docs/` に残す（結論・日付・範囲・未対応） | 社内エンジニアだけで「たぶん大丈夫」で Go |
| 4. Go / No-Go | Go ならカタログに Backoffice を掲載し、名乗れる範囲だけを書く。No-Go なら P16-デモ に戻す | 部分実装を全面準拠のように見せる |
| 5. 運用 | 監査ログ・バックアップ実演・BYO 給与／会計 SaaS 手順をゲート項目にする | 評価 LICENSE のまま実在従業員の本番給与 |

レビュー依頼の最小パッケージ: (a) `minutes-v1` 契約と非金額境界、(b) デモレートが fiction である明示、(c) 名乗る予定の帳票リスト、(d) staging の認証境界。

## 社会の仕組み（初心者向け・概要）

※ 製品の法令アドバイスではない。日本の給与まわりのざっくり地図。細部は税理士／社労士・国税庁資料が正。

### なぜ給料から税金や社保を引くのか

| 仕組み | 何のため | 誰がやる |
| --- | --- | --- |
| **源泉徴収** | 従業員の所得税を、会社が給料から天引きして国（税務署）に納める。個人が毎月自分で納めなくてよいようにする前払い | 会社（給与支払者） |
| **社会保険・労働保険** | 健康保険・厚生年金・雇用保険など。会社と本人で負担を分け、給料から本人負担分を天引きして納付 | 会社が手続き・納付 |
| **年末調整** | 毎月の源泉は概算。年末にその年の正しい税額を再計算し、足りなければ追加徴収・多すぎれば還付（多くは給与で精算） | 会社が従業員から申告を集め計算。確定申告が必要な人は別途本人が行うこともある |
| **源泉徴収票** | 「その年、会社がいくら払い、いくら所得税を預かったか」の証明書。確定申告・転職・住宅ローン等で使う | 会社が作成し **従業員に交付**。税務署への提出は別ルール（給与支払報告書など） |

「給与計算」＝ 出勤時間×単価だけではない。**総支給 − 控除（税・社保など）＝ 手取り** を出し、振込・納付・帳票まで含める。

### 帳票は国が決めるか

はい。所得税・年末調整まわりは **国税庁が様式を定めている**（例: 給与所得の源泉徴収票、扶養控除等申告書）。社保は日本年金機構・協会けんぽ等の手続き様式。ソフトウェアはそれに合わせて PDF／電子データを出す。自社オリジナル様式で「源泉徴収票です」とは名乗れない。

交付方法: 紙の交付が伝統だが、**電子交付（PDF 等）も法令上の条件を満たせば可**（同意・見読可能性など。詳細は専門家確認）。「印刷必須」ではないが、**正しい様式・正しい記載・交付義務の履行**が本質。

### 専門家レビューはいつか

| タイミング | 目的 |
| --- | --- |
| **開発・商用名乗り前（P16-規制名乗り）** | 「この製品／運用で名乗ってよいか」の設計レビュー。一度きりではなく、大きな法令改正・機能追加のたびに再確認 |
| **導入時（顧客ごと）** | 顧客の就業規則・賃金規程・被保険者区分に合わせた設定。税理士／社労士顧問が担当することが多い |
| **毎年（運用）** | 年末調整の実務・料率改定・法令改正の追随。顧問契約で毎年見るのが普通。「最初の年だけ見て終わり」にはしない |

製品側の P16-規制名乗り は **開発時の名乗りゲート**。顧客の毎年の年末調整実務そのものではない。

### 国への提出 vs 社員への交付（超要約）

- **源泉徴収票** → 原則 **従業員に渡す**（転職時・年末など）。税務署提出は対象・方法が別（電子／書面の区分あり）
- **年末調整の結果** → 多くは給与で還付・追徴。会社は源泉所得税を税務署に納付し、市区町村へ **給与支払報告書** 等も出す
- **確定申告** → 年末調整で完結しない人（副業・医療費控除など）が **本人** が行う
