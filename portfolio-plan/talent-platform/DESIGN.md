# P10 talent-platform — 設計方針

## この資料の使い方

実装チャットでは次を渡す。

- `portfolio-plan/00-overview.md`
- 本ファイル
- `portfolio-idea/27-job-matching-platform.md`

面接予約の結合時は `calendar/DESIGN.md`。推薦結合時は `recommend/DESIGN.md`。

## 対応アイデア

- 27 求人マッチング基盤

予約（11）と推薦（20）は **このリポジトリに再実装しない。** クライアントとして呼ぶ。

## 目的

架空 IT 求人と候補者の検索・応募・ステータス管理。就職活動ドメインそのものなのでペルソナが語りやすい。検索品質（フィルタ、ファセット、日本語）が本領。

## リポジトリ構成（ポリレポ）

検索インデックスとトランザクション DB は更新パターンが違う。Web も候補者/企業で同じ SPA でよいが、API と indexer は分ける。

| リポジトリ | 役割 |
| --- | --- |
| `pf-talent-web` | 候補者検索 UI、企業の求人管理、応募者一覧 |
| `pf-talent-api` | 求人・応募・プロフィールの正。OpenAPI |
| `pf-talent-search` | インデックス更新ワーカー。初期は API 内 FTS でもよい |
| `pf-talent-infra` | Compose |

初期（求人 200 件）は `pf-talent-search` を作らず Postgres FTS だけ、と DESIGN に書いてある通り段階化してよい。件数が増えたら OpenSearch を足し、リポジトリを追加する。ポリレポ方針は「必要になったら indexer を独立させる」こと。

200 件のうちから 3 リポジトリ必須にすると空洞化する。**開始はモノレポ相当の 2 リポジトリ（web + api）でよく、search は api のパッケージ。** 独立デプロイしたくなったらリポジトリを割る。

実装チャットでは次の段階を守れ。

1. `pf-talent-web` + `pf-talent-api`（FTS）
2. インデックス同期が遅延ジョブになったら `pf-talent-search` を分離

## 技術スタック

| 層 | 採用 |
| --- | --- |
| Web / API | Next.js, NestJS または Go |
| DB | PostgreSQL。年収は数値範囲 |
| 検索 | まず `tsvector` + `pg_trgm`。必要なら OpenSearch + 日本語解析 |
| 認証 | P01。ロール: candidate, employer, admin |
| 予約 | P05 |
| 推薦 | P07 namespace=`jobs` |

## 設計思想

- **求人の正は RDB。** 検索インデックスは派生
- **応募時に求人と履歴書をスナップショット。** あとから求人文面が変わっても当時を残す
- **スクレイピングしない。** シードは自作の架空データ
- **推薦は付加。** 検索が本体

## 実装順序

1. ✅ 企業・求人 CRUD、公開/非公開
2. ✅ 候補者プロフィール・応募状態機械・求人モデル拡充（スライス13）
3. ✅ 検索フィルタ（q, employmentType, remote, skills, salary）（スライス14）
4. ✅ 保存検索と新着（バッチ最小形。API 内 run endpoint）（スライス15）
5. ✅ P05: 書類通過後に面接スロットを提示（スライス16）
6. P07: 類似求人。精度が人気順に負けるなら UI に出さない
7. ファセット件数、管理の通報

## 実装上の注意点

- 応募者情報の権限。他社に漏れない
- スキルタグの正規化（React / React.js）をマスタ化
- 「応相談」年収は null 範囲 + フラグ。文字列ソートしない
- 実在企業名・実在人物をシードに使わない
- 公開デモは応募メールを実送せず Mailhog

## 他プロジェクトとの契約

- P05: employer の `sub` がホスト。イベントタイプ `interview-30m`
- P07: item は job id、interaction は view/bookmark/apply
- P13: 個人を含まない集計（職種別応募数）だけエクスポート可

## デモ

- フィルタを足すと件数が一致する
- 候補者と企業で見える応募が違う
- （任意）面接予約完了でステータスが「面接」になる

## 非目標

- 実在求人のクローリング
- 課金・掲載プラン
- ATS 全機能（課題管理は P04 に任せ、埋め込まない）
