# P08 content-platform — 設計方針

## この資料の使い方

実装チャットでは次を渡す。

- `portfolio-plan/00-overview.md`

- `portfolio-idea/07-tech-blog-cms.md`
- `portfolio-idea/09-url-shortener-analytics.md`

画像は `media-platform/DESIGN.md`。3-tier 適用時は `cloud-platform/DESIGN.md`。

## 対応アイデア

- 07 技術ブログ CMS
- 09 URL 短縮 + クリック分析

## 目的

技術発信と、記事・デモ URL の短いリンクを **公開コンテンツ基盤** にする。ブログ単体でも成立するが、短縮を別製品にするとログイン・ドメイン・分析が二重になる。ホットパス（リダイレクト）だけプロセスを分ける。

このブログに、他プロジェクトの設計判断（本 DESIGN 群の要約）を記事として書くと、就職活動の自己紹介と実装が一致する。

## リポジトリ構成（ポリレポ）

リダイレクトはレイテンシと悪用耐性が別物。Next.js に 302 を載せない。

| リポジトリ | 役割 |
| --- | --- |
| `pf-content-blog` | 公開ブログ SSG/ISR、管理 CMS、Draft Mode |
| `pf-content-shortener` | Go。Redis + Postgres。`GET /:code` のみ高速経路 |
| `pf-content-infra` | Compose。ブログから短縮 API を呼ぶ設定 |

管理画面で「この記事の短縮 URL を作る」が統合の UX。短縮単体の API も残し、アイデア 09 のダッシュボードを管理画面の一タブにする。

## 技術スタック

| 層 | 採用 |
| --- | --- |
| ブログ | Next.js, MDX, PostgreSQL, Tailwind |
| 短縮 | Go, Redis, PostgreSQL, クリックは非同期 |
| 画像 | P03。未完成時はローカル `/public` |
| 認証 | 管理画面のみ P01。公開記事は匿名 |
| ホスティング | ブログは Vercel や Cloudflare でも可。短縮は常駐が向く |

## 設計思想

- **公開側は CDN で速い。** 管理側だけ動的
- **短縮コードは予測困難。** 連番禁止
- **クリック計測でリダイレクトを待たない**
- **公開デモの短縮先は許可リストまたはログイン必須作成**（オープンリダイレクト／フィッシング対策）

## 実装順序

1. Markdown の静的ブログ（記事 1 本）
2. DB 駆動 CMS、下書き、RSS、sitemap
3. OG 画像、Draft Mode
4. 短縮サービス MVP（リダイレクト + 作成 API）
5. 管理画面から記事に紐づけ、日次グラフ
6. P03、P01、レート制限、k6 の簡単な計測を README に

## 実装上の注意点

- 管理画面を検索エンジンに載せない
- コメント欄は最初付けない（スパム）
- 短縮は `javascript:` 拒否、http(s) のみ
- 生 IP の長期保存をしない。国推定するなら短い保持
- 記事スラッグと短縮コードの名前空間を混ぜない

## 他プロジェクトとの契約

なし（上流）。下流として P02 の 3-tier 適用候補。P11 の OpenAPI ポータルに短縮 API を登録する。

## デモ

- 下書きプレビューが非公開のまま見られる
- 記事シェア用短縮リンクのクリックがグラフに出る（非同期なので数秒遅れ可）
- Lighthouse の結果を盛らずに載せる

## 非目標

- メディア企業級 CMS
- 独自ドメインをユーザーが繋ぐマルチテナント短縮
