# リポジトリ脆弱性診断レポートツール

依存関係の既知脆弱性、シークレット検出、Dockerfile の設定ミスをスキャンし、レポートを出す開発者向けセキュリティツールです。攻撃手順や悪用 PoC は含めず、防御・検出・修正提案に徹します。セキュリティ志望、プラットフォーム志望向けです。

## 概要

Git リポジトリ（ローカルパスまたは GitHub URL）を入力すると、言語を推定し、依存ロックファイルを解析、OSV / GitHub Advisory 等の公開データベースと照合します。結果を HTML/PDF/Markdown で出力し、CI でも使える CLI を用意します。

## 就職活動でのアピールポイント

- ソフトウェアサプライチェーン（SBOM の基礎）
- 静的な設定検査（IaC、Docker）
- 誤検知との付き合い方、重大度の説明
- CLI UX、終了コード（CI ゲート）
- セキュリティを「壊す」ではなく「直す」側で語れる

## 解決する課題

依存の更新漏れや、誤ってコミットしたシークレット、root ユーザーの Docker イメージに気づきたい。

## 想定ユーザー

開発チーム。デモは意図的に古い依存を含むサンプルアプリ（自分で作った脆弱な練習用 repo）。

## 主要機能

### 必須（MVP）

- CLI: `scan ./project`
- 対応: npm の package-lock、Python の uv.lock / poetry.lock / requirements、Go の go.sum のうち 1〜2 生態系から開始
- 既知 CVE の一覧（パッケージ、版、重大度、修正版）
- シークレットの正規表現検出（AWS キー風、秘密トークン風）。実キーは自分の環境に置かない
- Markdown レポート

### 推奨

- GitHub Action として使える
- SARIF 出力（GitHub Code Scanning に載せられる）
- Dockerfile 検査（latest タグ、USER root など）のルールセット
- 無視リスト（`.scannerignore`）と理由コメント
- Web UI でレポート閲覧、プロジェクト履歴

### 発展

- IaC（tfsec 相当を自前ルールで少数）
- ライセンス違反の検出
- 自動 PR（Dependabot の模倣）は権限が重いので任意

実装してよいのは検出とレポート、修正の提案です。エクスプロイトコード、攻撃手順、PoC は入れません。

## 画面 / CLI 構成

| 入口 | 役割 |
| --- | --- |
| CLI | CI の主戦場 |
| Web（任意） | 過去レポート |
| GitHub Action | PR コメント |

## API 概要（Web がある場合）

- `POST /scans`（repo upload または clone は危険なので、成果物 JSON を受ける方が安全）
- `GET /scans/:id`

公開 SaaS として任意リポジトリを clone させると、SSRF やサプライチェーンリスクがあるため、ポートフォリオでは CLI 優先が無難です。

## 技術スタック（推奨）

| 層 | 候補 |
| --- | --- |
| CLI | Go または Rust（単一バイナリが強い）、または Python（ecosystem 解析が楽） |
| 脆弱性 DB | OSV API、GitHub Advisory（利用規約を守る、結果をキャッシュ） |
| ルール | YAML で追加できる形 |
| テスト | フィクスチャとなる小さな lock ファイル |
| 配布 | GitHub Releases |
| Web | 任意で Next.js |

## アーキテクチャ

parse lock → パッケージ座標（purl）→ OSV クエリ（バッチ、キャッシュ）→ ルールエンジン → reporter。ネットワーク失敗時はキャッシュまたは明確なエラー。

## データモデル（概要）

- スキャン結果 JSON スキーマ（tool version, findings[]）
- finding: id, severity, package, installed, fixed, file, line, ruleId

## セキュリティ・品質

- スキャン対象をワークスペース外に出さない
- 検出したシークレットはレポートでマスク（先頭末尾のみ）
- 依存 DB への DoS にならないようキャッシュ
- 本ツール自身の lock もスキャンするメタさ

## 実装の進め方

1. 1 言語の lock パースと OSV
2. レポートと CLI 終了コード
3. シークレットと Docker ルール
4. Action
5. フィクスチャテスト

## 工数目安

- MVP: 2 週間
- 推奨: 3〜4 週間

## 面接での話し方

「誤検知をゼロにできないので、無視リストと根拠を残せるようにした」「スキャンは修正のための入力」と話すと成熟して見えます。攻撃者視点の話は、防御側の設計（入力検証、権限）に限定します。
