# ファイル共有ストレージ（Dropbox ミニ）

アップロード、フォルダ、共有リンク、権限、大容量ファイルを扱うストレージアプリです。オブジェクトストレージと署名付き URL、ウイルススキャンの「入れ場所」まで設計できると、バックエンド力がはっきり出ます。

## 概要

ユーザーごとに容量クォータ付きのクラウドストレージです。フォルダ階層、プレビュー、共有リンク（期限・パスワード）、バージョン履歴の簡易版を実装します。

## 就職活動でのアピールポイント

- マルチパートアップロード、署名付き URL
- メタデータ DB と実体（S3）の分離
- クォータ、重複排除（任意、コンテンツハッシュ）
- 共有リンクの認可モデル
- 非同期サムネイル生成

## 解決する課題

大きな成果物や画像を、メール添付ではなくリンクで渡したい。期限付きで社外に渡したい。

## 想定ユーザー

個人と小チーム。デモ容量は 100MB 程度で十分です。

## 主要機能

### 必須（MVP）

- フォルダ作成、ファイルアップロード / ダウンロード / 削除
- パンくず、一覧（名前、サイズ、更新日）
- 容量クォータ表示
- 共有リンク（読み取り、期限）
- ログイン必須のマイファイル

### 推奨

- ドラッグ＆ドロップ、進捗バー、再開可能なアップロード
- 画像・PDF のプレビュー
- ファイルバージョン（上書き時に旧オブジェクトを残す）
- チームフォルダとロール
- ゴミ箱（一定期間）
- 検索（ファイル名）

### 発展

- 全文 OCR、文書検索
- 重複排除
- クライアント暗号化

## 画面構成

| 画面 | 役割 |
| --- | --- |
| マイドライブ | エクスプローラ風 |
| アップロード | 進捗 |
| 共有リンク管理 | 無効化 |
| 公開ダウンロード | トークン付き、ログイン不要 |

## API 概要

- `POST /files/presign` → クライアントが S3 へ PUT
- `POST /files/complete`（etag, size, hash を検証）
- `GET /files/:id/download` → 署名付き GET へ 302
- `POST /share-links`
- フォルダ CRUD

実ファイルを API サーバー経由で全部流すとメモリとタイムアウトで死ぬ、という説明ができるようにします。

## 技術スタック（推奨）

| 層 | 候補 |
| --- | --- |
| フロント | Next.js、uppy または自前 XHR |
| バックエンド | Go / NestJS |
| メタデータ | PostgreSQL |
| オブジェクト | MinIO（開発）、S3 / R2（本番） |
| ジョブ | サムネイル（sharp）、PDF は任意 |
| インフラ | Docker Compose（app + minio + db） |

## アーキテクチャ

ブラウザ → presign → S3 PUT → complete で `files` 行を確定。失敗した未完成オブジェクトはライフサイクルで削除。共有リンクは `share_links` を見て署名 URL を発行。

## データモデル（概要）

- `folders`（parent_id, path）
- `files`（storage_key, size, mime, sha256, version）
- `share_links`（token, expires_at, password_hash, max_downloads）
- `usage`（user_id, bytes_used）

## セキュリティ・品質

- パス操作（`../`）禁止、サーバーで path を正規化
- MIME は拡張子だけ信じない
- 共有トークンは高エントロピー
- クォータ超過は complete 時に拒否し、S3 オブジェクトを削除
- 公開デモはファイル種類を画像とテキストに制限すると安全

## 実装の進め方

1. ローカルディスク保存の CRUD（動作確認）
2. S3 署名付き URL に置換
3. 共有リンク
4. プレビュージョブ
5. クォータとゴミ箱
