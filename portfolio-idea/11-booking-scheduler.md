# 予約・日程調整ツール（Calendly ミニ）

空き時間の公開、予約、リマインド、タイムゾーン、重複防止を扱うドメインです。カレンダー UI と排他制御が本領で、SaaS 企業の選考と相性が良いです。

## 概要

ホストが週次の空きルールを設定し、ゲストが公開ページから枠を予約します。確定後に双方へメールし、Google カレンダー連携は任意です。キャンセルと変更、バッファ時間まで入れると実務らしいです。

## 就職活動でのアピールポイント

- タイムゾーン変換の正確さ
- スロット生成アルゴリズム（ルール → 具体日時）
- ダブルブッキング防止（トランザクション、ユニーク制約）
- 公開ページの UX、フォーム
- Webhook / メール / ICS ファイル

## 解決する課題

メールで「来週どうですか」と往復するコストを減らします。面接予約やメンタリング、クリニックの簡易予約にも転用できます。

## 想定ユーザー

個人の面談予約、社内の 1on1、小さな店舗の予約。デモは「カジュアル面談 30 分」イベントタイプ。

## 主要機能

### 必須（MVP）

- イベントタイプ（時間、期間、バッファ、曜日ごとの空き）
- 公開予約ページ（日付選択 → 時間選択 → フォーム）
- 予約確定、重複不可
- キャンセルリンク（トークン付き）
- ホスト側の予約一覧
- タイムゾーン選択（ゲスト）

### 推奨

- リマインド（24h 前、1h 前）ジョブ
- ICS 添付、Google Calendar API（OAuth）
- 予約上限（1 日 n 件）、最短予約期限（例: 3 時間先まで不可）
- 複数イベントタイプ（15 / 30 / 60 分）
- ホストの例外（特定日のブロック）

### 発展

- チームのラウンドロビン
- 支払い（前金）は決済連携が必要で任意
- Zoom リンク自動発行

## 画面構成

| 画面 | 役割 |
| --- | --- |
| ホスト設定 | 空きルール、例外日 |
| 公開ページ | ゲスト向け |
| 予約完了 | 概要とカレンダー追加 |
| ホストダッシュボード | 今後の予約 |
| 連携 | Google OAuth |

## API 概要

- `GET /public/:slug/slots?date=&tz=`
- `POST /public/:slug/book`（slotStart, name, email, idempotencyKey）
- `POST /bookings/:token/cancel`
- `GET /me/event-types`

スロット計算はサーバー側で行い、クライアントの計算を信じません。

## 技術スタック（推奨）

| 層 | 候補 |
| --- | --- |
| フロント | Next.js、TypeScript、date-fns-tz または Temporal（可能な環境） |
| バックエンド | NestJS / Rails |
| DB | PostgreSQL（`tstzrange` と exclusion constraint があると強い） |
| ジョブ | リマインド用ワーカー |
| メール | SES / Resend |
| インフラ | Docker、GitHub Actions |

PostgreSQL の `EXCLUDE USING gist (tstzrange(...))` で重複予約を DB レベルで防ぐと、面接で非常に良い話になります。

## アーキテクチャ

空きルールと既存予約、例外日からスロットを生成。予約 INSERT はトランザクション＋一意制約。リマインドは `scheduled_jobs`。カレンダー同期は失敗しても予約自体は成功させる（外部 API の切り離し）。

## データモデル（概要）

- `users`, `event_types`（duration, buffer, min_notice）
- `availability_rules`（dow, start_local, end_local, timezone）
- `date_overrides`
- `bookings`（start_at, end_at, guest_email, status）
- `booking_tokens`

## セキュリティ・品質

- 公開ページは PII を出しすぎない（他ゲストの名前を見せない）
- キャンセルトークンは十分長い
- メール列挙対策（予約時の応答を均一に）
- 大量スロット生成の上限（期間は 2 週間など）

## 実装の進め方

1. ルールとスロット API、単体テスト（TZ ケースを先に書く）
2. 予約と exclusion
3. 公開 UI
4. メールとリマインド
5. Google 連携（任意）

## 工数目安

- MVP: 2〜3 週間
- 推奨: 4 週間

## 面接での話し方

夏時間、`Asia/Tokyo` と `America/Los_Angeles` のゲスト、をテストした話が効きます。「クライアントの ISO 文字列をそのまま信じない」もポイントです。

- TZ テストケース一覧
- ダブルブッキングを 2 タブで試す手順
- デモ用公開 URL
