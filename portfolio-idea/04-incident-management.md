# 障害インシデント管理（PagerDuty ミニ）

SRE / インフラ / バックエンド志望で特に効く題材です。アラート受信、オンコール、インシデントのライフサイクル、事後レポートまでを小さな SaaS として作ります。

## 概要

監視ツールからの Webhook を受けてインシデントを起票し、オンコール担当へ通知し、対応状況をタイムラインで共有します。障害対応の「運用」をプロダクトにした点が、通常の CRUD アプリとの差別化になります。

## 就職活動でのアピールポイント

- Webhook 受信、署名検証、冪等性
- 状態機械（triggered → acknowledged → resolved）
- オンコールローテーション、エスカレーション
- リアルタイムタイムライン
- ポストモーテムテンプレート、SLO の基礎用語を実務に結びつけて話せる

## 解決する課題

アラートがメールに埋もれ、誰が対応中かわからない状態を避けます。「今起きている障害」と「誰がアサインされているか」を一箇所に集約します。

## 想定ユーザー

少人数 SRE / 開発チーム。デモでは架空サービス「Checkout API」の障害を流します。

## 主要機能

### 必須（MVP）

- サービス（監視対象）登録
- アラート受信 Webhook（JSON）。同一 `dedup_key` はインシデントを集約
- インシデント一覧（重大度、ステータス、担当）
- Ack / Resolve、担当者アサイン
- タイムライン（コメント、状態変更）
- オンコールスケジュール（週次ローテーション、簡易）

### 推奨

- エスカレーションポリシー（5 分無応答で次の人）
- 通知チャネル（メール、Slack Incoming Webhook）
- メンテナンスウィンドウ（その間は通知抑制）
- 重大度（SEV1〜SEV4）とページング要否
- ポストモーテム作成（時系列の自動下書き）

### 発展

- ステータスページ（外部公開、障害中のみ更新）
- Prometheus Alertmanager 互換のペイロード
- オンコールカレンダーの iCal 出力

## 画面構成

| 画面 | 役割 |
| --- | --- |
| インシデントボード | 未解決が上、SEV 色分け |
| インシデント詳細 | タイムライン、Ack ボタン |
| サービス設定 | Webhook URL、統合キー |
| オンコール | 今週の担当、交代 |
| ポストモーテム | テンプレ編集 |

## API 概要

- `POST /integrations/:key/events`（外部から。HMAC 署名）
- `GET /incidents`, `POST /incidents/:id/ack`
- `GET /oncall/current`
- `POST /incidents/:id/comments`
- 内部ジョブ: エスカレーションtick

## 技術スタック（推奨）

| 層 | 候補 |
| --- | --- |
| フロント | Next.js、TypeScript |
| バックエンド | Go または Node.js（イベント処理向き） |
| DB | PostgreSQL |
| キュー | Redis + ワーカー（遅延ジョブでエスカレーション） |
| 通知 | SendGrid / SES、Slack Webhook |
| インフラ | Docker Compose、GitHub Actions |
| 観測 | 自分自身のヘルスチェックエンドポイント、構造化ログ |

## アーキテクチャ

外部監視 → HTTPS Webhook → 署名検証 → 冪等キーで upsert → インシデント作成 → 通知ジョブ。Ack が無い場合は遅延キューで次の担当者へ。UI は SSE でタイムライン更新。

## データモデル（概要）

- `services`, `integration_keys`
- `incidents`（status, severity, dedup_key, service_id）
- `incident_events`（timeline）
- `schedules`, `schedule_layers`, `overrides`
- `escalation_policies`, `notification_logs`

## セキュリティ・品質

- Webhook の署名必須、生ペイロードのサイズ制限
- 統合キーは表示時マスク、ローテーション可能
- 冪等性テスト（同じイベントを 2 回送ってもインシデントは 1 件）

## 実装の進め方

1. インシデント CRUD と状態遷移
2. Webhook と冪等集約
3. オンコールと通知
4. エスカレーションジョブ
5. ポストモーテムとデモ用「擬似アラート」ボタン

## 工数目安

- MVP: 2〜3 週間
- 推奨: 4〜5 週間

## 面接での話し方

「監視とインシデントの違い」「アラート疲れを減らすために集約した」と話すと SRE 志望として通りやすいです。実際に Alertmanager から叩けると評価が一段上がります。
