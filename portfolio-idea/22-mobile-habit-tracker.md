# モバイル習慣トラッカー（React Native / Flutter）

ネイティブ寄りのモバイル実装を見せるポートフォリオです。Web ばかりの人との差別化になります。通知、ローカル DB、チャート、ウィジェット（任意）まで含めると完成度が出ます。

## 概要

毎日の習慣（運動、読書、水分）を記録し、ストリーク、リマインダー、週次レポートを提供します。バックエンドを付けると認証と複数端末同期もアピールできます。

## 就職活動でのアピールポイント

- モバイル UI（リスト、ジェスチャー、アクセシビリティ）
- ローカル永続化とマイグレーション
- プッシュ / ローカル通知の許可フロー
- アプリストアを出さなくても TestFlight / Internal testing または APK の説明
- オフラインファースト

## 解決する課題

習慣を「続けている実感」とリマインドで支える。複雑な SNS 機能は足さない。

## 想定ユーザー

個人。デモは 5 習慣 × 30 日のシード。

## 主要機能

### 必須（MVP）

- 習慣の CRUD（頻度: 毎日 / 週 n 回）
- 当日のチェック、取り消し
- ストリーク表示、カレンダー
- ローカル通知（指定時刻）
- 統計（達成率）

### 推奨

- クラウド同期（ログイン）
- ウィジェット（Android は比較的現実的）
- ホーム画面ショートカット
- テーマ、ハプティクス
- CSV エクスポート
- アーカイブ（終わった習慣）

### 発展

- Apple Watch / Wear は工数が大きい
- ソーシャルランキングはプライバシーと荒らしの話が必要で必須ではない

## 画面構成

| 画面 | 役割 |
| --- | --- |
| 今日 | チェックが主操作 |
| 習慣詳細 | カレンダーとメモ |
| 統計 | 週/月 |
| 設定 | 通知、アカウント |

## API 概要（同期する場合）

- `GET/POST /habits`
- `PUT /habits/:id/logs/:date`
- 差分同期（`updated_at`）

同期しない場合は完全ローカルでも、モバイル力は伝わります。その場合はバックアップ（ファイル共有）があるとよいです。

## 技術スタック（推奨）

| 層 | 候補 A | 候補 B |
| --- | --- | --- |
| フレームワーク | React Native（Expo） | Flutter |
| 言語 | TypeScript | Dart |
| ローカル DB | SQLite（drizzle / watermelondb） | sqflite / drift |
| 通知 | expo-notifications | flutter_local_notifications |
| 状態 | Riverpod / RN なら zustand |
| バックエンド | 任意（Supabase でも自前でも） |
| 配布 | EAS / Flutter build |

求人が React なら Expo、Android ネイティブ寄りや UI の綺麗さなら Flutter、と選ぶとよいです。

## アーキテクチャ

UI → domain（ストリーク計算は純関数で単体テスト）→ repository（SQLite）→ 任意で remote。通知は OS スケジューラ。日付はユーザー TZ で「今日」を決める。

## データモデル（概要）

- `habits`（schedule, reminder_time, color）
- `habit_logs`（habit_id, local_date, completed）
- `sync_meta`

## セキュリティ・品質

- 通知許可の説明文
- クラウド同期時は他ユーザーの習慣が取れないこと
- 日付変更（深夜 0 時、TZ 変更）のテスト

## 実装の進め方

1. 今日のチェックと SQLite
2. 統計とカレンダー
3. 通知
4. 同期（任意）
5. ストア用アイコン、スクリーンショット、README の動画
