# URL 短縮サービス＋クリック分析

小さなドメインで、API 設計・リダイレクト性能・分析基盤・スパム対策をまとめて見せられる定番です。単純な CRUD に終わらせず、キャッシュと計測の設計まで含めると評価が上がります。

## 概要

長い URL を短いコードに変換し、アクセス時に 302/301 で飛ばします。ダッシュボードでクリック数、参照元、国（IP から粗い推定）、日次推移を見ます。Bitly のミニ版です。

## 就職活動でのアピールポイント

- 短い識別子の生成（衝突、予測困難性）
- ホットパス（リダイレクト）の低レイテンシ設計
- クリックイベントの非同期記録
- レート制限、不正 URL 対策
- キャッシュ戦略（Redis）、DB 負荷分離

## 解決する課題

キャンペーン URL や QR 用に短いリンクが欲しい。クリックが何件あったかを後から見たい。

## 想定ユーザー

マーケ担当と開発者（API 利用）。デモは自分のブログ記事への短縮リンク。

## 主要機能

### 必須（MVP）

- ログインして URL 登録、カスタムスラッグ任意
- `https://short.example/Ab3X9` でリダイレクト
- 有効期限、有効/無効
- クリック総数、日別グラフ
- 管理画面での一覧・削除

### 推奨

- QR コード生成
- UTM を保ったまま短縮
- 参照元、User-Agent の集計（ボット除外の簡易ルール）
- 公開 API（API キー、レート制限）
- パスワード付きリンク、ワンタイムリンク
- CSV エクスポート

### 発展

- リンクツリー（1 スラッグで複数 URL を時間帯や A/B で振分）
- 独自ドメイン接続（CNAME）は DNS 検証が必要で重いので任意

## 画面構成

| 画面 | 役割 |
| --- | --- |
| 作成フォーム | 長い URL → 短い URL |
| リンク詳細 | グラフと最近のクリック |
| API キー | 開発者向け |
| 設定 | デフォルト有効期限 |

## API 概要

- `POST /api/links` `{ url, slug?, expiresAt? }`
- `GET /api/links/:id/stats`
- リダイレクトはアプリの別エントリ（できるなら軽量なサービスに分離）
- `GET /:code` → 302 Location

## 技術スタック（推奨）

| 層 | 候補 |
| --- | --- |
| 管理 UI | Next.js |
| リダイレクト | Go または Cloudflare Workers（レイテンシの話ができる） |
| DB | PostgreSQL（リンクマスタ） |
| キャッシュ | Redis（code → url） |
| 分析 | クリックはキュー（Redis Stream / SQS）→ バッチ集計、または ClickHouse 相当は過剰なので Postgres 日次テーブル |
| インフラ | Docker、GitHub Actions、Fly.io / Cloud Run |

## アーキテクチャ

リダイレクト経路: エッジ or Go → Redis GET → なければ DB → キャッシュ → 302。クリック記録は応答後に非同期。管理画面は別デプロイでも同一でも可。

識別子は nanoid（衝突耐性）＋ DB unique。連番は予測されるので使いません。

## データモデル（概要）

- `users`, `api_keys`（hashed）
- `links`（code, url, expires_at, is_active）
- `click_events`（link_id, ts, referer, ua, country）※生 IP は短期間またはハッシュ
- `click_daily`（link_id, date, count）

## セキュリティ・品質

- javascript: や data: を拒否、http(s) のみ
- オープンリダイレクトの悪用対策（フィッシング警告ページを挟む選択肢）
- マルウェア URL リストは任意。README で「学習用、公開デモは許可ドメインのみ」でも誠実
- レート制限、CAPTCHA（公開作成フォームがある場合）

## 実装の進め方

1. 短縮とリダイレクト、テスト
2. 認証付き管理画面
3. 非同期クリック集計
4. API キーとレート制限
5. 負荷の目安を README に書く（k6 の簡単なシナリオがあると強い）

## 工数目安

- MVP: 1〜2 週間
- 推奨: 3 週間

## 面接での話し方

「なぜリダイレクトを Next.js に載せなかったか」「クリックを同期 insert しない理由」が核心です。ベンチマークが荒くても、測った事実があれば十分です。
