# リアルタイム共同編集ドキュメント

複数カーソルで同じ Markdown を編集するアプリです。CRDT または OT の導入、衝突解決、プレゼンスを扱います。難易度は高めですが、完成すると印象が非常に強いです。

## 概要

Google Docs の極小版。文書の作成、共有リンク、同時編集、履歴（任意）を提供します。まずは 1 文書・プレーンテキストまたは Markdown に範囲を絞ります。

## 就職活動でのアピールポイント

- CRDT（Yjs / Automerge）の利用とサーバーの役割
- WebSocket の接続管理、ドキュメント部屋
- エディタ統合（CodeMirror / TipTap）
- 権限（編集 / 閲覧）
- オフライン編集と再同期（可能な範囲）

## 解決する課題

議事録を画面共有しながら 1 人が入力する状態を、同時編集に変えます。

## 想定ユーザー

少人数のドキュメント共有。デモは 2 ブラウザでカーソルが見えること。

## 主要機能

### 必須（MVP）

- 文書作成、共有 URL
- 同時編集（文字単位の競合が壊れない）
- 他ユーザーのカーソルと名前
- 認証または「リンクを知っている人は編集可」の 2 モード
- 自動保存（サーバーまたは永続化プロバイダ）

### 推奨

- Markdown プレビュー分割
- コメント（行や選択範囲。共同編集より難しいので後回しでも可）
- 文書一覧、ゴミ箱
- 読み取り専用リンク
- 接続状態インジケータ、再接続

### 発展

- 画像埋め込み
- バージョン履歴（スナップショット）
- 音声は不要

自前で OT をゼロから書くとバグが visibile なので、Yjs などのライブラリを使い、「なぜそれが必要か」「サーバーは何をするか」を説明できることが評価点です。ゼロから書いた場合は範囲をテキストのみに。

## 画面構成

| 画面 | 役割 |
| --- | --- |
| 文書一覧 | 自分の docs |
| エディタ | 共同編集の主画面 |
| 共有ダイアログ | リンクと権限 |

## API 概要

- REST: 文書メタデータ CRUD
- WS / y-websocket: ドキュメント同期
- 永続化: y-websocket の DB アダプタ、または定期スナップショット

## 技術スタック（推奨）

| 層 | 候補 |
| --- | --- |
| エディタ | TipTap + Yjs、または CodeMirror 6 + Yjs |
| 同期 | y-websocket、Hocuspocus |
| フロント | Next.js、TypeScript |
| DB | PostgreSQL（文書バイナリ + メタ） |
| 認証 | 既存 IdP または簡易 JWT |
| インフラ | Docker、Sticky session または Redis なしの単一同期サーバーを明記 |

## アーキテクチャ

各クライアントが Y.Doc を持ち、更新をサーバーが中継・永続化。サーバーはマージの真実を持たず、CRDT の更新をリレーします。スケールするときは文書 ID でシャーディング、と README に書きます。

## データモデル（概要）

- `documents`（id, title, yjs_state, updated_at）
- `document_members`（role）
- `share_links`

## セキュリティ・品質

- 文書 ID は推測困難
- WS でも認可（購読時にトークン検証）
- 巨大ペーストのサイズ制限
- XSS（プレビュー時の Markdown サニタイズ）

## 実装の進め方

1. 単一ユーザーのエディタ + 保存
2. Yjs 同期 + カーソル
3. 認証と共有
4. 永続化と再接続
5. プレビューと制限事項

## 工数目安

- MVP: 2〜3 週間
- 推奨: 4〜5 週間

## 面接での話し方

「最後の書き込みが勝つではカーソル位置が壊れる」「CRDT を使った」まで言えれば十分です。中身の論文を暗記する必要はありません。制限（大規模編集、モバイル IME）を自分で書いてあると誠実です。
