# チーム向けナレッジベース（社内 Wiki）

ドキュメントの作成・検索・権限管理を備えた Wiki です。Markdown、履歴、全文検索を実装すると、情報設計とバックエンドの基礎がまとめて伝わります。Notion / Confluence のミニ版として説明しやすい題材です。

## 概要

階層ページ、共同編集に近いロック、タグ、全文検索を持つドキュメント基盤です。IT 企業の「情報が属人化しない」課題に直結するため、業務理解もアピールできます。

## 就職活動でのアピールポイント

- Markdown レンダリング、XSS 対策、画像アップロード
- ツリー構造データの取得（隣接リスト / nested set / materialized path）
- 全文検索、ハイライト、サジェスト
- 版管理（diff）、権限（スペース単位）
- SEO ではなく「情報設計」と「検索品質」の話ができる

## 解決する課題

チャットに散らばった手順書を、検索可能な単一の情報源にまとめます。新人が「デプロイ手順」をすぐ見つけられる状態を目指します。

## 想定ユーザー

社内エンジニア、カスタマーサポート、少人数スタートアップ。面接では「10〜50人の開発組織」を想定するとよいです。

## 主要機能

### 必須（MVP）

- スペース（チーム）作成とメンバー権限（管理者 / 編集 / 閲覧）
- ページの階層（親ページ、並び順）
- Markdown エディタ（プレビュー付き）
- ページ公開 / 下書き
- 全文検索（タイトル優先、本文）
- 添付画像のアップロード（オブジェクトストレージ）

### 推奨

- ページ履歴と diff 表示、特定版へのロールバック
- 目次自動生成、見出しアンカー
- お気に入り、最近閲覧
- コメントスレッド、`@mention`
- テンプレート（障害報告、ADR、議事録）
- エクスポート（Markdown / PDF）

### 発展

- 同時編集の警告（編集ロック、または簡易 CRDT）
- Slack 通知、公開 API
- AI による要約・類似ページ提案（外部 LLM API。キーはサーバー側のみ）

## 画面構成

| 画面 | 役割 |
| --- | --- |
| スペース一覧 | チームごとの入口 |
| サイドバー＋本文 | ツリーと記事 |
| 検索結果 | ハイライト付きヒット |
| 履歴 | 版の比較 |
| 権限設定 | 招待とロール |

## API 概要

- `GET /spaces/:id/pages/tree`
- `GET/PUT /pages/:id`（本文は Markdown を保存、HTML は都度またはキャッシュ）
- `GET /pages/:id/versions`
- `GET /search?q=&spaceId=`
- `POST /assets`（署名付き URL または multipart）

## 技術スタック（推奨）

| 層 | 候補 |
| --- | --- |
| フロント | Next.js、TypeScript、CodeMirror 6 または Milkdown、Tailwind |
| バックエンド | NestJS / Rails / Django |
| DB | PostgreSQL（`ltree` または materialized path） |
| 検索 | PostgreSQL FTS、または Meilisearch / OpenSearch |
| ストレージ | S3 互換（MinIO でローカル） |
| レンダリング | markdown-it / remark、DOMPurify 相当のサニタイズ |
| インフラ | Docker、GitHub Actions、Cloudflare R2 または AWS S3 |

## アーキテクチャ

編集は API に Markdown を保存し、表示時にサニタイズ済み HTML を返します。検索は非同期でインデックス更新（ページ保存後にキュー）すると、拡張の話ができます。ツリーは 1 クエリで取れるパス方式が説明しやすいです。

## データモデル（概要）

- `spaces`, `space_members`
- `pages`（parent_id, path, title, body, status）
- `page_versions`（editor_id, body, created_at）
- `attachments`, `page_views`, `stars`

## セキュリティ・品質

- Markdown 内の `javascript:` リンクや raw HTML を除去
- 添付の MIME / サイズ制限、ウイルススキャンは発展扱い
- 閲覧権限のないページは検索結果にも出さない（重要）

## 実装の進め方

1. ページ CRUD とツリー
2. Markdown と画像
3. 検索と権限の一貫性
4. 履歴・diff
5. デプロイとデモ用サンプル Wiki（「オンボーディング手順」など）

## 工数目安

- MVP: 2 週間
- 推奨: 4 週間

## 面接での話し方

「検索結果から権限外のページを除外した理由」「ツリー取得の N+1 をどう避けたか」を具体的に話します。サンプル記事を充実させると、プロダクト sensemaking も伝わります。

## 公開時のチェックリスト

- デモ用スペースと閲覧専用アカウント
- 検索のスクショまたは短い動画
- 権限と検索のテストケースを README に記載
