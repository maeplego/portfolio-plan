# リアルタイム在庫・オペレーションダッシュボード

倉庫や店舗の在庫、受注、アラートをリアルタイムで眺める管理画面です。WebSocket、集計、権限、大きなテーブルのパフォーマンスをまとめて見せられます。フロント＋バックエンド双方の力作になります。

## 概要

SKU ごとの在庫、入出庫、閾値割れアラート、拠点別ヒートマップを提供します。EC の 05 番と組み合わせても、単独の「運用ダッシュボード」としても成立します。

## 就職活動でのアピールポイント

- 大量行の仮想スクロール、フィルタ、保存済みビュー
- WebSocket / SSE によるプッシュ更新
- 集計クエリの最適化、マテリアライズドビュー
- RBAC（本部 / 店舗）
- データ可視化（在庫推移、欠品率）

## 解決する課題

欠品に気づくのが遅い、店舗と本部で数字が違う、という運用課題を、単一のリアルタイム画面で減らします。

## 想定ユーザー

小売の本部オペレーターと店舗スタッフ。デモは 3 店舗 × 200 SKU。

## 主要機能

### 必須（MVP）

- 在庫一覧（検索、カテゴリ、拠点、在庫数ソート）
- 入庫 / 出庫 / 棚卸の登録
- 安全在庫を下回ったら行を警告色
- ダッシュボード（欠品数、今日の出庫、回転の悪い SKU）
- ロール（本部は全拠点、店舗は自拠点のみ）

### 推奨

- 在庫変動のライブフィード
- グラフ（7 日の在庫推移、カテゴリ構成）
- CSV インポート（棚卸）とバリデーションエラー表示
- 保存済みフィルタ、列の表示/非表示
- しきい値の拠点別設定

### 発展

- 発注点で発注候補リストを自動生成
- バーコード（カメラ）入力
- 地図上の店舗在庫

## 画面構成

| 画面 | 役割 |
| --- | --- |
| オペレーションボード | KPI カード＋アラート |
| 在庫グリッド | メイン作業画面 |
| 入出庫フォーム | 数量、理由、参照番号 |
| 商品マスタ | SKU 管理 |
| ライブフィード | 変動イベント |

## API 概要

- `GET /skus?siteId=&q=&cursor=`
- `POST /stock-movements`
- `GET /metrics/overview`
- `GET /alerts`
- WS: `stock.updated`, `alert.raised`

ページングは offset ではなく cursor にすると、面接で話ができます。

## 技術スタック（推奨）

| 層 | 候補 |
| --- | --- |
| フロント | Next.js または React + Vite、TanStack Table、Recharts / ECharts、TanStack Query |
| バックエンド | NestJS / Go |
| DB | PostgreSQL（移動履歴が正、在庫残高は集計またはトリガ更新） |
| リアルタイム | Redis Pub/Sub + WebSocket |
| インフラ | Docker、GitHub Actions |

## アーキテクチャ

`stock_movements` を追記し、`stock_balances` をトランザクション内で更新します。更新後に Redis へ publish。ダッシュボード KPI は 30 秒キャッシュでも、グリッドは即時反映にします。

## データモデル（概要）

- `sites`, `skus`, `categories`
- `stock_balances`（site_id, sku_id, qty, version）
- `stock_movements`（type, qty, reason, actor_id）
- `alert_rules`, `alerts`

## セキュリティ・品質

- 負在庫を許可するか設定化。許可しない場合はサーバーで拒否
- 同時棚卸の競合は version で検出
- インポートはプレビュー→確定の 2 段階

## 実装の進め方

1. マスタと移動、残高更新
2. グリッドと権限
3. KPI とグラフ
4. ライブ更新
5. CSV インポート

## 工数目安

## 面接での話し方
