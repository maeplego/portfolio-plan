# リアルタイムチャット＋通知基盤

WebSocket、既読、プレゼンス、通知を実装する定番コミュニケーションアプリです。ありきたりにしないために、配信保証・順序・スケールの設計をドキュメント化します。

## 概要

1対1 とグループチャンネル、メッセージ、画像、既読、入力中表示、プッシュ通知（またはメール）を提供します。Slack / Discord の極小版です。

## 就職活動でのアピールポイント

- 双方向通信、再接続、メッセージの欠落補完
- メッセージ順序（サーバー時刻、シーケンス番号）
- 未読カウントの効率的な更新
- ファイルアップロード
- 水平スケール時の Pub/Sub（Redis）

## 解決する課題

チームやコミュニティが、履歴の残るチャットで非同期＋同期コミュニケーションを行う。

## 想定ユーザー

小チーム。デモは 2 ユーザーで「入力中」と既読が見えること。

## 主要機能

### 必須（MVP）

- サインアップ、DM、グループ作成・招待
- メッセージ送受信、履歴のカーソルページング
- オンライン状態（最終ログインでも可）
- 未読バッジ
- 画像 1 枚添付

### 推奨

- 入力中（typing）のブロードキャスト（debounce）
- 既読ウォーターマーク
- メッセージ編集・削除（tombstone）
- 絵文字リアクション
- メンションと通知
- 検索（チャンネル内）
- 再接続時に `afterSeq` で差分取得

### 発展

- スレッド
- 音声は範囲过大
- E2EE は実装が重いので「将来課題」に回すのが誠実

## 画面構成

| 画面 | 役割 |
| --- | --- |
| チャンネルリスト | 未読付き |
| タイムライン | 仮想スクロール |
| メンバー | 招待 |
| 設定 | 通知オンオフ |

## API 概要

- REST: 履歴 `GET /channels/:id/messages?before=`
- WS: `message.create`, `typing`, `presence`, `ack`
- `POST /channels/:id/attachments`（先に URL、後でメッセージ）

## 技術スタック（推奨）

| 層 | 候補 |
| --- | --- |
| フロント | Next.js または React、TanStack Virtual |
| リアルタイム | Socket.IO（フォールバック）または素の WebSocket |
| バックエンド | Node.js / Go / Elixir（Phoenix はリアルタイムの説得力が高い） |
| DB | PostgreSQL |
| Pub/Sub | Redis（複数サーバー化の布石） |
| ストレージ | S3 / MinIO |
| インフラ | Docker、GitHub Actions |

Elixir/Phoenix を使えると差別化になりますが、チームの技術に合わせて選んでください。

## アーキテクチャ

メッセージは DB に INSERT してから WS で配ります（先に WS だけだと履歴が欠ける）。マルチインスタンスでは Redis Pub/Sub で他ノードへ。未読は `channel_members.last_read_seq` と最新 seq の差。

## データモデル（概要）

- `users`, `channels`, `channel_members`
- `messages`（channel_id, seq, body, deleted_at）
- `attachments`
- `receipts` または last_read_seq
- `push_subscriptions`（発展）

`seq` はチャンネル内単調増加（トランザクションで採番）。

## セキュリティ・品質

- チャンネル所属チェックを WS イベントでも実施
- メッセージの長さ制限、画像 MIME
- XSS（Markdown やリンク）
- レート制限（連投）

## 実装の進め方

1. REST 履歴＋単純 WS
2. seq と再接続差分
3. 既読・未読
4. Redis で複数インスタンス対応の説明または実装
5. 添付と通知
